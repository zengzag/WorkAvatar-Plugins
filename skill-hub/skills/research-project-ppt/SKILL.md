# 科研答辩与汇报 PPT 美学系统

本技能定义一套"学术蓝 · 理性秩序"的视觉标准，并把标准写成可测量、可验收的约束；同时规定一条参考驱动、评审闭环的生成流水线。它不规定分几章、写谁的名字；这些由材料决定。技能只回答两件事：**同样的内容，怎样组织才符合这套美学；从材料到成稿，按什么顺序推进。**

适用：项目申报、中期检查、结题答辩、科技奖答辩、实验室/团队汇报等**高密度评审场景**。
不适用：学术会议报告（一页一个观点、正文 18–24 pt 的稀疏版式，不属于本系统）、通用商业提案、创意营销。

核心文件：

- [`references/aesthetic-system.md`](references/aesthetic-system.md)：美学命题、版面坐标、语义色板、区域底色、线/形语义、字阶、密度与量化验收（规范主体）。
- [`references/pipeline.md`](references/pipeline.md)：五阶段流水线、参考库结构、页级 brief、四维评审与红线（流程主体）。
- [`references/composition-grammar.md`](references/composition-grammar.md)：8 种抽象构图语法与选择表。
- [`references/page-archetypes.md`](references/page-archetypes.md)：十类常见页面原型到构图的映射与各自规则。
- [`references/implementation.md`](references/implementation.md)：可选的 PPTX 参考实现，不是规则。
- [`assets/aesthetic-tokens.json`](assets/aesthetic-tokens.json)：机器可读阈值，审计脚本使用。

## 风格命题

- 蓝白主色、信息密度高、卡片分区清楚、数字目标突出、每页有结论。
- 蓝色负责结构；红色负责目标与差距；绿色负责已完成与达标；橙色只做提醒。同页强调色 ≤2。
- 分组用**区域底色**表达逻辑，不用装饰表达：同页 ≤3 区，单区着色 ≤25% 页面面积，全 deck 区域色调 ≤2 种。
- 标题固定为"编号块 + 标题 + 通栏细线"，下面紧跟一句页首结论。
- 深色陈述页（封面、章节、结束）占 15–25%；浅色证据页承担信息。
- 每页一个视觉重心；主模块面积 ≥ 第二模块的 1.5 倍（并列构图除外，但只能有一个强调焦点）。
- 装饰只保留线、细边、低对比底纹；禁止阴影、水印、模板店标识、3D、光晕。

## 流水线

完整输入输出、放行条件与评审 JSON 见 [`pipeline.md`](references/pipeline.md)。这里只给顺序与闸门。

0. **判断场合。** 高密度评审（申报/答辩/检查/汇报）→ 用本系统；学术会议报告 → 换稀疏版式，不套本系统的密度档。

1. **检索（可选，默认开）。** 从参考库取 2–3 个"同信息形态 + 同构图"的锚点，只借结构与分组方式；无参考库就跳过，不伪造参考。

2. **规划。** 把每页材料写成 brief：材料事实、信息形态、页首结论、构图、主/支撑/强调元素、阅读顺序、本页不放什么。描述要具体到"谁指向谁、哪个数字被放大"。

3. **造型。** 按美学阈值把 brief 变成视觉参数：区域底色、形状与线语义、字阶、色彩预算。只做视觉干预，不改语义；已有合规描述就保留。

4. **渲染。** 写成 `deck.json` 输出可编辑 PPTX；无 `[warn]`、`--audit --strict` 通过，再导出 PNG 目检。

5. **评审。** 按忠实/精炼/可读/美学四维逐页检查，红线一票否决；输出带页码与修法的 JSON，只改被点名的页，最多 3 轮，`pass` 才交付。

需要新配图时，先走图稿子流水线（[`pipeline.md`](references/pipeline.md) 第 8 节）：检索风格锚点 → 写图注与图意 → 套用分区/线形语义 → 出 PNG → 按同一四维评审，再嵌入页面。

信息形态不是内容模板：把每页材料归为八类（单一陈述、索引集合、单一证据、两组对照、有序步骤、并列模块、单一主体、同类目录），按信息形态选构图与原型；一页只用一个构图，同一原型连续出现必须换构图。

## 美学底线

1. 画布 16:9（13.333×7.5 in / 1280×720 px）；左右边距 0.42–0.55 in；对齐轴 ≤2。
2. 标题 = 编号块（0.62×0.45 in 主蓝白字）+ 标题（≤20 汉字）+ 通栏 0.75 pt 细线；位置全 deck 一致。
3. 每个证据页有页首结论句（16–18 pt 加粗，1–2 行）；收束页有通栏主蓝结论带，一句话。
4. 语义色：红 `#B80000` 只标目标/差距/风险/关键数字；绿 `#2E8B57` 只标完成/达标；橙 `#E87722` 只做提醒；同页强调色 ≤2；红色文字 ≤3 处/页。
5. 字体家族 ≤2、字重 ≤2；中文无衬线，封面可宋体；页面标题 24–28 pt；变量与符号用衬线斜体，标签用无衬线。
6. 字号分两档且不混档：投影档正文 ≥14 pt、表格 ≥10 pt；高密度审阅档正文 ≥12 px、表格 ≥11 px。
7. 数字层级：目标值 28–40 pt 红加粗，单位 12–14 pt；数字必须有单位、来源、对比对象。
8. 中文行长 18–34 字；文本块 ≤3 行；每模块要点 ≤6；层级 ≤2 级。
9. 证据页 2–4 个主模块；陈述/索引/目录型页可为 1 个主构图；墨迹覆盖 55–75%（上限 80%）；留白 ≥25%。
10. 图像 1–3 张/证据页；照片统一比例细边框；图注 9–10 pt；一页一张主图。
11. 区域底色只表达逻辑分组：同页 ≤3 区、单区 ≤25% 页面面积、全 deck ≤2 色调；虚线边框只圈定范围，不表示流程方向。
12. 线语义固定：实线为主流程/因果，虚线为辅助流/可选路径/逻辑范围；单页箭头 ≤5，平头线表抑制。
13. 形状语义固定：圆角矩形=流程/模块，直角矩形=数据/矩阵，仓储形=数据库/平台；同实体同形同色，2D 与 3D 不混用。
14. 边框 0.75/1/1.5 pt `#C9D8EA`；圆角全 deck 统一；阴影 0；渐变 ≤2 色标。
15. 页脚有来源与页码（9 pt 灰）；正文对比 ≥7:1；无水印、无他人 logo、无无关装饰。

## 量化验收速查

| 指标 | 通过条件 |
|---|---|
| 编号块/页脚/结论带 | 位置全 deck 一致 |
| 页首结论句 | 每个证据页 1 句，≤2 行 |
| 深色页占比 | 15–25%（浅色封面家族 5–25%） |
| 强调色 | 同页 ≤2 种；面积 2–5% |
| 红色文字 | ≤3 span/页，只标语义 |
| 正文字号 | 投影 ≥14 pt / 高密度 ≥12 px，不混档 |
| 数字层级 | 目标值 28–40 pt 红加粗 |
| 行长 / 块行数 | 18–34 字 / ≤3 行 |
| 主模块 / 要点 | 证据页 2–4，陈述/目录型 1 / ≤6 |
| 区域底色 | ≤3 区/页，≤25% 页面面积/区，全 deck ≤2 色调 |
| 线/形语义 | 实线主流程、虚线辅助或范围；流程圆角、数据直角 |
| 图像 | 1–3（目录 ≤6），有图注 |
| 墨迹覆盖 / 留白 | 55–75%（≤80%）/ ≥25% |
| 缩放可读 | 缩到 50% 仍能读出标题、结论、关键数字 |
| 评审结论 | verdict 为 pass，或已按意见修订且无遗留红线 |

完整验收表与测量方法见美学系统第 11 节。

## 参考实现

```bash
python scripts/render_deck.py deck.json -o out
python scripts/render_deck.py deck.json -o out --audit
python scripts/render_deck.py deck.json -o out --audit --strict
```

- 依赖 Python 3.9+、`python-pptx`、`Pillow`。
- `custom` 布局的 `zone` 块用于区域底色分组（`tone` 取 `ice/mist/cream/lavender`），用法见 [`implementation.md`](references/implementation.md)。
- `examples/sample-deck.json` 只用于演示版式；姓名、单位、指标均为虚构占位，不是内容模板。
- 实现默认为高密度审阅档；用于现场投影时按美学系统第 3 节上调字号。审计只覆盖可计算项，构图是否成立仍需目检。

## 反模式

- 每页三张等宽卡片；所有页同一构图；编号块/页脚位置漂移。
- 跳过评审直接成稿；评审只挑措辞，放过结构与密度问题。
- 参考锚点照抄文案与数字；为了"统一"抹掉领域特征。
- 用阴影、渐变、图标、光晕撑场面；去掉装饰后页面散架。
- 区域底色当装饰：每页几块彩色底、底色饱和、区域不表达分组。
- 线/形语义混乱：同一含义混用实线虚线、虚线围边、流程用直角、数据用圆角、2D 与 3D 混搭。
- 红绿橙当装饰：整段红字、绿色铺卡片、同页强调色超过两种。
- 为塞内容把正文降到下限以下；一页 6 个以上模块；整页文字墙。
- 只有标题没有页首结论句；结论带写废话或超过一句话。
- 数字没有单位、来源、对比对象；目标值与现状值分不清。
- 三张图片比例不一、被拉伸、压字、无图注。
- 把版式当内容脚本：规定必须写谁、必须分几章、必须出现哪些字段。
- 把这套高密度系统用于学术会议报告。

## 交付检查

- [ ] 场合判定正确；会议报告已改用稀疏版式。
- [ ] 参考锚点只贡献结构，未带入他人文案、数字、配色。
- [ ] 每页 brief 的元素都能在成稿中找到对应槽位，且都在支撑页首结论。
- [ ] 构图选择与信息形态匹配，且一页只有一个重心。
- [ ] 所有量化指标通过审计；无 `[warn]` 与 `[audit]`。
- [ ] 视觉重心、留白、对齐、图像裁切经 PNG 目检成立。
- [ ] 编号块、分隔线、结论带、页脚位置全 deck 一致。
- [ ] 每个证据页有页首结论句；结论带只有一句话。
- [ ] 红绿橙语义正确；数字有单位、来源、对比。
- [ ] 区域底色 ≤3 区、单区 ≤25% 页面面积、≤2 色调；虚线只圈定范围。
- [ ] 线/形语义与图注一致；同实体同形同色。
- [ ] 评审 verdict 为 pass，或有修订记录且无遗留红线。
- [ ] 新增配图通过图稿四维评审；图内无图题、无黑底，图注与图一致。
- [ ] 深色页比例、密度节奏、构图轮换符合跨页节奏约束。
- [ ] 缩到 50% 仍能读出标题、结论、关键数字。
- [ ] 没有把示例姓名、示例单位、示例指标、水印带入正式稿。

# 构图语法

构图语法回答“这类信息该以什么视觉结构出现”，不回答“这一页该写什么内容”。选择依据是信息形态（单一陈述、导航、证据、对照、序列、并列、单一主体、目录），不是行业或职位。

所有构图共享同一条底线：12 栏栅格、40 边距、2 条对齐轴、2–4 个主模块、单一焦点。

## 0. 通用骨架

```
A 区：页眉锚点（可选）        高度 10%
B 区：主战场                  高度 72–79%
C 区：结论带（可选）          高度 5.5%
```

- A 区只放一个标题锚点，靠左上；右侧保持空。
- B 区必须有一个主模块，面积 ≥ 第二模块的 1.5 倍。
- C 区只在“整页可压缩成一句判断”时出现；索引页与陈述页不使用。
- 页眉、结论带一旦使用，全套保持一致；不允许部分页面有、部分页面无。

## 1. 陈述场 `Statement Field`

**信息形态**：一个判断、一个主题、一个态度，没有需要并读的细节。

```
┌────────────────────────────────────┐
│            A 区：极简锚点            │
│                                    │
│        ┌──────────────────┐        │
│        │  一个文字块 55–65% │        │
│        │  最多 2 行         │        │
│        └──────────────────┘        │
│              1 条强调线             │
│                                    │
│        C 区：元信息带 20–28%        │
└────────────────────────────────────┘
```

- 深色背景；负空间 ≥45%；文字块居中或左对齐但不与页眉争夺。
- 主文字块宽 55–65%，位于画布 38–45% 高度。
- 只允许 3 个文本块：主陈述、辅助陈述、元信息。
- 强调只用一条金线或一个金色短语；红色不用于深色场。
- 适用：开场、章节停顿、收束、单一结论；不适用需要证据并读的页面。

## 2. 索引轨 `Index Rail`

**信息形态**：一个并列集合（3–6 项），需要显示当前位置或顺序。

```
┌──────────────┬──────────────────────┐
│              │  01 ─────────────    │
│  竖向锚点     │  02 ─────────────    │
│  28–30%      │  03 ─────────────    │
│              │  04 ─────────────    │
└──────────────┴──────────────────────┘
```

- 左轨 28–30%，用深色或低明度色块；右侧为 4–6 个等高条目。
- 当前项用主色填充，其余项低对比（文字对比 ≤3:1）；不允许两项同时高亮。
- 条目高度 68–80，间距 18–20；序号与文字之间用 1px 竖线。
- 左轨只放一个竖向标题与一个微型标签；不放正文。
- 适用：目录、章节过渡、流程索引；不适用需要解释细节的页面。

## 3. 证据场 `Evidence Field`

**信息形态**：一个必须被看清的证据对象（表格、矩阵、图、截图），周围只有少量解释。

```
┌────────────────────────────────────┐
│  标题锚点                           │
│  ┌──────────────────────────────┐  │
│  │                              │  │
│  │   主证据 55–70% 宽 × 50–70% 高 │  │
│  │                              │  │
│  └──────────────────────────────┘  │
│  ┌────────────┐  ┌────────────┐    │
│  │ 支撑说明 1  │  │ 支撑说明 2  │    │
│  └────────────┘  └────────────┘    │
└────────────────────────────────────┘
```

- 主证据占内容区 55–100% 宽（默认通栏）、50–70% 高；文字解释 ≤2 个模块。
- 支撑说明可以是一句判断 + 1–2 个数据，不得抢主证据的焦点。
- 表格/图内文字 11–12；主证据边框 0.75–1px；不使用阴影。
- 适用：对比、现状、指标、系统结构、实验数据；不适用纯态度陈述。

## 4. 双场 `Dual Field`

**信息形态**：两组需要并读的信息，存在明确对照轴（前/后、内/外、问题/对策、现状/目标）。

```
┌────────────────┬────────────────────┐
│                │                    │
│   场 A 48–50%   │   场 B 48–50%       │
│   主级          │   主级（镜像）       │
│                │                    │
└────────────────┴────────────────────┘
        共享结论带（可选）
```

- 两场各 48–50%，间距 1–1.5%；两场标题必须同一字阶。
- 只允许 2 个焦点；若两场完全等重，必须存在对照轴，否则改成证据场。
- 每场内部 3–5 条信息，最多 1 张图；图不得跨过中线。
- 适用：对照、双路线、双问题；不适用三项以上并列。

## 5. 序列轨 `Sequence Track`

**信息形态**：有先后顺序的 3–5 步，或三个阶段。

```
┌────────────────────────────────────┐
│  标题锚点                           │
│  ┌────┐ → ┌────┐ → ┌────┐ → ┌────┐ │
│  │ 01 │   │ 02 │   │ 03 │   │ 04 │ │
│  └────┘   └────┘   └────┘   └────┘ │
│  ┌──────────┐  ┌──────────┐        │
│  │ 说明卡 1  │  │ 说明卡 2  │        │
│  └──────────┘  └──────────┘        │
└────────────────────────────────────┘
```

- 步数 3–5；每步等宽、等高；方向单一（左→右或上→下）。
- 箭头 5–8px，只做连接；单页箭头 ≤5。
- 最多一个“当前步”用强调色；其余步用中性色。
- 步骤框内只放 1 个短标题 + 1 行说明；细节放下方说明卡（≤2 张）。
- 同一阶段内的步骤可用一个区域底色包住，跨区箭头表示阶段推进；同页 ≤3 区，虚线只圈范围。
- 适用：流程、路线、阶段计划；不适用并列关系。

## 6. 星座场 `Constellation`

**信息形态**：3–4 个并列模块，每个模块内部有独立的小结构。

```
┌──────────┐ ┌──────────┐ ┌──────────┐
│ 模块 A    │ │ 模块 B    │ │ 模块 C    │
│ 图/表/要点 │ │ 图/表/要点 │ │ 图/表/要点 │
└──────────┘ └──────────┘ └──────────┘
```

- 3–4 个等宽模块，间距 1–1.5%；模块高度一致。
- 最多一个模块用强调色；其余模块只用中性色 + 主色标题条。
- 每个模块内部最多 1 个图 + 4 条要点，或 1 个小表 + 2 条要点。
- 模块标题条高度统一（4% 画布高），字号统一。
- 适用：并列研究方向、能力、措施、成果；不适用需要强主次的页面（改用证据场）。

## 7. 焦点场 `Focal Field`

**信息形态**：一个主体（人、设备、产品、现场、证书）需要被识别，周围是支持信息。

```
┌──────────────┬──────────────────────┐
│              │  标题/说明 1–2 块      │
│  主体 30–40%  │                      │
│  4:5 / 1:1   │  证据：表/要点/小图     │
│              │                      │
└──────────────┴──────────────────────┘
```

- 主体占内容宽 18–30%，比例 4:5 或 1:1；不得拉伸。
- 主体位于左三分之一或右三分之一；不居中，避免与标题轴冲突。
- 右侧只允许 2 个文本块 + 1 个证据对象；总模块 ≤3。
- 主体图 1px 边框；图注 10–11px；不加阴影。
- 适用：人物、设备、现场、证书、单一产品；不适用并列集合。

## 8. 目录场 `Catalogue`

**信息形态**：6–12 个同类小项，需要整齐可比。

```
┌────┐ ┌────┐ ┌────┐ ┌────┐
│ 01 │ │ 02 │ │ 03 │ │ 04 │
└────┘ └────┘ └────┘ └────┘
┌────┐ ┌────┐ ┌────┐ ┌────┐
│ 05 │ │ 06 │ │ 07 │ │ 08 │
└────┘ └────┘ └────┘ └────┘
```

- 2–4 列、2–3 行；每项等宽等高；间距一致。
- 每项只放 1 个短标签 + 1 行说明（≤2 行）；不放长段落。
- 每行最多一个强调项；没有强调项也可成立。
- 图片项统一比例；同一页不混用 4:3 与 16:9。
- 适用：成果清单、证书、设备、指标矩阵；不适用需要解释机制的页面。

## 选择表

| 信息形态 | 首选构图 | 备选 |
|---|---|---|
| 单一判断 / 主题 / 态度 | 陈述场 | 焦点场 |
| 并列集合 + 当前位置 | 索引轨 | 目录场 |
| 一个必须看清的证据 | 证据场 | 焦点场 |
| 两组对照 | 双场 | 证据场 |
| 3–5 步顺序 | 序列轨 | 星座场 |
| 3–4 个并列模块 | 星座场 | 目录场 |
| 单一主体 + 支持信息 | 焦点场 | 双场 |
| 6–12 个同类小项 | 目录场 | 星座场 |

### 页面原型映射

答辩/汇报中常见页面类型到构图与规则的映射见 [`page-archetypes.md`](page-archetypes.md)：背景与需求、现状与差距、目标与指标、技术路线、机制与原理、结果、团队、平台与条件、成果与预期、总结。原型不匹配时回到本表按信息形态选择。

## 构图失败模式

- 三张等宽卡片连续出现在每一页（模板感的最大来源）。
- 双场 50:50 但没有对照轴，读者不知道该先看哪边。
- 序列超过 5 步，或箭头比步骤标题更醒目。
- 星座场里四个模块都强调，导致没有焦点。
- 焦点场主体居中，与页眉形成两条竞争轴。
- 目录场混用不同图片比例，边缘参差。
- 陈述场塞入表格或 3 条以上解释，失去“停顿”功能。

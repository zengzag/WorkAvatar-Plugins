# 生成流水线

本文件定义从材料到成稿的五阶段流水线：**检索 → 规划 → 造型 → 渲染 → 评审**。它吸收"参考驱动 + 闭环评审"的思路，但不调用图像生成模型：每一阶段的产物都是可编辑的 PPTX 元素与可核对的结构描述。

边界：美学阈值见 [`aesthetic-system.md`](aesthetic-system.md)，构图见 [`composition-grammar.md`](composition-grammar.md)，页面类型见 [`page-archetypes.md`](page-archetypes.md)，实现细节见 [`implementation.md`](implementation.md)。本文件只规定阶段顺序、输入输出与放行条件，不重复数值标准。

## 0. 场合判定（前置闸门）

- 高密度评审（申报/答辩/检查/汇报）→ 走完整五阶段。
- 学术会议报告 → 不适用本系统，改用一页一观点的稀疏版式。
- 时间极短 → 允许合并：跳过检索、规划与造型合并，但**评审至少一轮，量化审计不降级**。

## 1. 检索 Retriever

**目标**：为每类页面找 2–3 个结构锚点，学结构，不抄内容。

参考库条目只记录结构与视觉标签，不存原始材料：

```json
{
  "id": "ref-01",
  "intent": "现状与差距",
  "composition": "双场",
  "structure": ["左右对照", "右侧四列表格", "左侧瓶颈卡"],
  "visual": ["冰蓝区域底", "虚线分组", "红色目标值"],
  "source": "2025 年中期检查成稿第 6 页",
  "note": "只借分组方式，不借文案"
}
```

选择优先级：

1. **同信息形态 + 同构图**（最佳）。
2. **同构图、不同主题**（结构比主题更重要）。
3. **避免**：不同构图的锚点，例如拿"结果页主图"去画"机制页"。

规则：

- 参考库默认放在 `assets/reference-library.json`（上述条目的数组）；文件不存在即视为无参考库，直接跳过。
- 每页 2–3 个锚点，最多 5 个；锚点只影响结构、区域划分与间距，不复制文案、数字和具体配色。
- 没有参考库就跳过本阶段，直接按构图语法与原型生成；**不要伪造参考**。
- 参考库可由历史成稿积累；一份成稿可反哺 1–2 条条目，避免无限膨胀。

## 2. 规划 Planner

**输入**：单页材料、页码、场合、参考锚点（可选）。

**输出**：页级 brief（建议与 deck.json 同目录存放 `<slug>.brief.json`，也可只作为内部推演）：

```json
{
  "page": 4,
  "material": "本页要证明的事实，一句话",
  "intent": "两组对照",
  "claim": "页首结论句，不写套话",
  "composition": "双场",
  "elements": {
    "primary": "必须被看清的证据对象",
    "support": ["支撑说明 1", "支撑说明 2"],
    "emphasis": "唯一的强调焦点"
  },
  "priority": ["第一眼", "第二眼", "第三眼"],
  "exclusions": ["本页不放的内容"]
}
```

规则：

- 描述必须具体到"谁指向谁、什么与什么对齐、哪个数字被放大"；"科技感、简洁大气"不是描述。
- 一页一个构图、一个视觉重心；材料装不下就拆页，不缩字号硬塞。
- **先写结论句，再排元素**；排完回头检查每个元素是否都在支撑结论。
- 标题只写主题，不写"概述 / 介绍 / 相关内容"。
- `exclusions` 必须非空：不写"不放什么"，页面一定会堆料。

## 3. 造型 Stylist

把 brief 变成具体视觉参数，**只做视觉干预，不改语义**。

- 先套美学阈值，再决定是否使用区域底色；区域底色只表达"逻辑分组 / 阶段 / 环境"，不做装饰。
- 先评估现有描述：已明确且合规就保留；只有缺细节、过时或杂乱时才按风格指南补全。为统一而统一会抹掉领域特征。
- 同一实体全 deck 同色同形；状态色只表达状态，不表达类别。
- 形状与线（详见美学系统第 7 节）：流程节点圆角矩形，数据/矩阵直角矩形，数据库/平台用仓储形；主流程实线，辅助/可选/逻辑范围虚线。
- 变量与符号用衬线斜体，标签用无衬线；中文字不倾斜。
- 禁止为"高级感"加阴影、光晕、3D、图标堆砌或高饱和底色。

放行条件：brief 的每个元素都能在 deck.json 中找到对应槽位；没有为了塞内容而突破字号下限。

## 4. 渲染 Renderer

- 一张幻灯片对应一个 brief；`layout` 与内容形态不匹配时用 `custom`，仍须满足美学阈值。
- 放行条件：无 `[warn]`（溢出、缺图）；`--audit --strict` 通过。
- 导出 PNG 逐页目检构图、焦点、留白与对齐；没有导出环境时退化为结构检查，并在交付说明中注明"未做像素级目检"。

```bash
python scripts/render_deck.py deck.json -o out --audit --strict
powershell -ExecutionPolicy Bypass -File scripts/preview_pptx.ps1 -Pptx out/<name>.pptx -OutDir out/png
```

## 5. 评审 Critic（闭环，1–3 轮）

每轮对每个内容页按四个维度检查；只输出问题与修订，不重写整份 deck。

| 维度 | 问什么 | 通过条件 |
|---|---|---|
| 忠实 `faithfulness` | 是否与材料一致，有无编造 | 模块、指标、结论、单位都有出处；内容不超出标题承诺的范围 |
| 精炼 `conciseness` | 视觉信噪比是否够高 | 每页一句结论；不逐字搬运正文；每模块 ≤6 条要点 |
| 可读 `readability` | 能否快速读懂 | 缩到 50% 仍可读出标题、结论、关键数字；无遮挡、溢出、断行 |
| 美学 `aesthetics` | 是否成立而不靠装饰 | 对齐、字阶、留白、区域与线语义一致；无模板感 |

### 红线（任一触发即 fail）

- **编造**：材料里没有的模块、指标、结论、单位。
- **矛盾**：箭头方向与因果相反；目标值与现状值混淆；同一实体两种颜色或两种形状。
- **越界**：页面内容超出标题/结论承诺的范围；把附件内容塞进主页面。
- **溢出**：文字截断、压字、图注缺失、图片拉伸。
- **文字墙**：整页正文；逐字搬运材料；一页超过 4 个模块。
- **失控**：元素重叠、箭头交叉成网、单页箭头超过 5 个。
- **装饰依赖**：阴影、发光、3D、水印、模板标识；同页强调色超过 2 种。
- **字体混用**：同页三族以上；中文斜体；变量用无衬线。

### 输出（严格 JSON）

```json
{
  "round": 1,
  "verdict": "revise",
  "slides": [
    {
      "page": 4,
      "dimension": "readability",
      "severity": "veto",
      "issue": "右侧表格第三列文字压线",
      "fix": "列宽 +0.3 in；仍不够则先删 2 行，再降到 10 pt"
    }
  ],
  "global": [
    {"issue": "第 3、5 页编号块下移 4 px", "fix": "统一回 0.62×0.45 in"}
  ],
  "passed_pages": [1, 2]
}
```

规则：

- `verdict` 只有 `pass` / `revise`；全部页面无红线且四维通过才 `pass`。
- `severity` 只有 `veto`（红线）、`major`（结构性）、`minor`（打磨）；红线必须当轮修掉。
- 每条问题必须带页码、维度、severity 和可执行修法；"再优化一下"不是问题。
- 修订优先顺序：**删内容 > 换构图 > 调对齐/栏宽 > 调字号**；不得先缩字号硬塞。
- 只改被点名的页；全局问题统一改，避免位置漂移。
- 同一页连续两轮同一问题未解决，回到构图层面重做该页，不再微调。
- 连续两轮无新增红线即停；最多 3 轮。剩余问题写进交付说明。
- 评审记录（轮次、verdict、遗留问题）随成稿交付；可写入 `out/review.json`，与 PPTX 同目录。

## 6. 降级与例外

| 情况 | 处理 |
|---|---|
| 无参考库 | 只跳过检索阶段，其余照常 |
| 无 PNG 导出环境 | 用审计 + 结构检查替代目检，并注明 |
| 时间紧 | 检索与造型合并、评审 1 轮；红线与量化审计不降级 |
| 用户提供现成 deck | 从评审阶段进入，先审计再评审，不重做已通过的页 |

## 7. 常见失败

- **锚点照抄**：结构像了，事实错了。锚点只借分组与间距。
- **brief 空话**："提升系统性能"这类描述会让造型阶段只能猜，最终页必然空。
- **评审只挑措辞**：结构与密度问题被放过，越改越花。
- **每轮重写整份 deck**：编号块、页脚位置漂移，一致性崩掉。
- **用缩小字号解决溢出**：审计能过，投影不可读。
- **跳过评审直接交付**：量化指标合格但构图不成立，属于未完成。

## 8. 图稿子流水线（可选）

页面需要机制图、架构图或结果图，而现有素材不足时，可先产出一张图，再按图像规范嵌入页面。流程思路取自 PaperBanana 的多智能体图示生成，本技能只借流程与评审维度，不打包其代码或模型调用。

1. **检索**：找 2–3 张同类科研插图作风格锚点，只借信息组织（分区、流向、图例），不借具体图形。
2. **规划**：把页级 brief 改写成图注 + 图意：图中出现哪些实体、谁指向谁、哪些是输入/输出、哪些是可选路径。不写"科技感"。
3. **造型**：套用本系统第 2、7 节——淡色分区、圆角流程/直角数据、实线主流程/虚线辅助、无衬线标签、无黑底、无 3D、无 emoji；颜色含义直接标在块上，不另附图例表。
4. **出图**：得到 PNG 后再嵌入；图内不放图题（"图 1：…"），图题只写在页面图注里。
5. **评审**：按同一四维检查——忠实（无编造模块）、精炼（不逐字搬正文）、可读（缩小后标签仍可读）、美观（分区与线语义一致）。

图稿红线：黑底、图题入图、乱码标签、箭头成网、元素外溢留下大片空白、3D 与 2D 混用、拉伸变形、图注与图不一致。任一项不通过就重做；重做两轮仍不达标，改用几何示意、表格或流程框，不拿低质图凑数。

嵌入约束：证据页 1–3 张、同页比例一致、1 px `#C9D8EA` 边框、图注 9–10 pt、一页一张主图；图占内容区 20–40%（结果页主图 50–65%）。
